# 정비자 앱 (apps/tech)

설비 알람을 받은 정비자가 원인을 좁히고, 매뉴얼 절차대로 점검·조치·재가동한 뒤 보고서를 내기까지를 한 흐름으로 안내한다.

- 사용자: 정비자 계정만 (`X-App: tech`, 쿠키 `tech_session`)
- 화면 크기: 고정 틀 1080 × 740 (현장 태블릿 기준)
- 갱신: 홈 5초, 진단 세션 3초 주기로 다시 조회
- 주소: `/` 홈, `/session/{id}` 진단 세션. 새로고침해도 같은 자리로 돌아온다.

## 공통 규칙

- 화면은 API가 준 값만 보여 준다. 원인 순위, 판정, 등급 같은 값을 앱이 만들지 않는다.
- 아직 보내지 않은 입력, 떠난 화면, 마지막으로 받은 지시는 기기에 둔다(`device.ts`). 홈에 갔다 와도 그대로 남는다.
- 입력은 세션 + 순번(seq)을 키로 보내서, 같은 입력이 두 번 반영되지 않게 한다.
- 상단 바: 로고, 현재 설비·단계, 홈 버튼(확인 없이 이동), 알림 종, 사용자, 다크 모드 버튼(이 기기에 기억, [0005](../decisions/0005-다크-모드-기능.md)).

## 화면

| 번호 | 화면 | 보이는 것 · 할 수 있는 것 | API |
| --- | --- | --- | --- |
| T01 | 로그인 | 정비자 계정으로 로그인. 역할이 다르면 서버가 거절(403 `role_mismatch`)한다 | `POST /api/login` |
| T02 | 홈 | 내 알람과 할 일 목록. 알람을 눌러 진단 세션을 연다 | `GET /api/tech/home`, `POST /api/tech/alarms/{id}/session` |
| T12 | 알림 패널 | 상단 종을 누르면 새 알람·할 일 목록. 새 알람이 오면 알림음 | `GET /api/tech/notifications` |
| T03 | 알람 | 증상, 계통, 기준 이탈 수, 추이, 센서 표, AI 해석, 찾은 과거 기록 수. 다음 행동은 "진단 보기" 하나 | `GET /api/tech/sessions/{sid}` |
| T04 | 진단 | 원인 후보 순위, 비슷한 과거 기록 3건, 다음 점검(미리보기)과 고른 이유. 첫 판정이 호출이면 강조 카드만 바뀐다 | 같은 세션 응답 |
| T05 | 잠금 · 사전 확인 | 잠금 전에는 1.2절 잠금 절차만 보이고 지시 내용은 내려받지 않는다. 잠금 뒤 사전 확인 절을 먼저 한다 | `POST /api/tech/sessions/{sid}/events` |
| T06 | 점검 지시 · 결과 입력 | 지시는 한 번에 하나, 건너뛰기 없음. 결과(정상/이상 등)와 메모 입력 | `POST .../events` |
| T07 | 확인 질문 | 결과가 맞지 않을 때 확인 질문과 소견. 뒤에는 직전 지시를 흐리게 보인다 | `POST .../events` |
| T14 | 매뉴얼 원문 | 지시에 연결된 매뉴얼 절 원문을 창으로 연다 | `GET /api/tech/sessions/{sid}/manual/{section}` |
| — | 과거 기록 | 비슷한 과거 기록을 눌러 상세를 창으로 본다 | `GET /api/records/{id}` |
| T08 | 조치 · 재가동 | 조치 내용, 재가동 체크, 재가동 후 값이 경계 안인지 | `POST .../events` |
| T10 | 파트장 호출 | 호출 요약 → 대기 → 보냄 → 답(3종) | `POST .../events` |
| T11 | 숙련자 인계 · 감시 마감 | 인계 또는 감시 기간 마감 | `POST .../events` |
| T09 | 보고서 | 세션 결과 요약 보고서 확인·확정. 확정하면 파트장 승인 대기로 간다 | `POST .../events` |
| T15 | 지난 화면 | 진행 표시에서 지나온 단계를 누르면 그때 값으로 보기 상태. 내가 입력한 결과·메모·측정값은 "이 기록 정정", 그 밖은 "메모 덧붙이기". 정정으로 지시가 바뀌면 확인 창에서 보내지 않은 입력이 지워진다고 알린다 | `GET .../history`, `POST .../corrections`, `POST .../notes` |

## 할 일 · 미정

- 로그아웃 버튼이 없다. API(`POST /api/logout`)는 있다.
- 백엔드 없이 화면을 보는 Mock 모드가 없다. 지금은 테스트(fixture)로만 백엔드 없이 동작한다.
- 화면 틀이 고정 크기라 태블릿 외 화면에서는 가운데에 작게 보인다.
- A/B 테스트 모드(`VITE_AB_TEST=1`)에서는 디자인 후보 B · C · D를 전환할 수 있다. 화면 · 순서는 같고 CSS만 다르다. 후보를 하나 고르면 평소 디자인으로 옮길지 정한다([0004](../decisions/0004-AB-테스트용-디자인-후보-3개.md)).
