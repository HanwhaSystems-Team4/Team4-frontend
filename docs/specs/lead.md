# 파트장 앱 (apps/lead)

정비자가 낸 보고서를 승인하고, 정비자 호출에 답하고, 매뉴얼 절별 권한 등급을 관리하고, 기록을 감사한다.

- 사용자: 파트장 계정만 (`X-App: lead`, 쿠키 `lead_session`)
- 화면 크기: 고정 틀 1280 × 620
- 갱신: 10초 주기로 다시 조회
- 주소: `/` 승인 대기, `/review/{id}`, `/calls`, `/calls/{id}`, `/grades`, `/audit`. 새로고침해도 같은 자리.

## 공통 규칙

- 화면은 API가 준 값만 보여 준다. 경고 문구, 답 선택지, 행동 문구는 서버가 준다.
- 틀: 왼쪽 고정 메뉴 4개(승인 대기, 처리할 호출, 권한 등급, 감사 기록)와 아래 사용자, 본문 머리(제목, 시각). 메뉴를 옮기면 본문만 바뀐다.

## 화면

| 번호 | 화면 | 보이는 것 · 할 수 있는 것 | API |
| --- | --- | --- | --- |
| L01 | 로그인 | 파트장 계정으로 로그인. 역할이 다르면 서버가 거절(403 `role_mismatch`) | `POST /api/login` |
| L02 | 승인 대기 | 요약 타일 3개, 승인 대기 보고서 표, 빈 목록 안내 | `GET /api/lead/overview` |
| L03 | 보고서 검토 | 보고서 내용. 그대로 승인, 수정 후 승인, 반려. 수정 문장의 근거 검사는 서버가 한다 | `GET /api/lead/reports/{id}`, `POST .../check`, `POST .../decision` |
| L04 | 처리할 호출 | 목록(유형, 설비, 시각, 필요한 작업, 보낸 사람). 상세에서 정비자 요약, 답 선택지, 처리 메모, 답 저장. D등급 호출에는 "승인 후 진행"이 없다. 정비자가 정정하면 정정 상자를 보인다 | `GET /api/lead/calls`, `GET /api/lead/calls/{id}`, `POST .../answer` |
| L05 | 권한 등급 | 절별 등급 표 전체("n절 중 n절 표시"), 등급 A~D 고르기, 낮춤·올림 경고를 확인해야 저장, 변경 기록(누가, 언제, 전, 후) | `GET /api/lead/grades`, `GET .../{section}/warning`, `POST .../{section}` |
| L06 | 감사 기록 | 필터 3개(설비, 사용자, 기간, 바꾸면 바로 걸러짐), 표(시각, 사용자, 앱, 행동, 대상, 최신순) | `GET /api/lead/audit` |

등급 배지 색은 의미가 정해져 있다: A 초록, B 파랑, C 주황, D 빨강.

## 할 일 · 미정

- 로그아웃 버튼이 없다. API(`POST /api/logout`)는 있다.
- 백엔드 없이 화면을 보는 Mock 모드가 없다.
