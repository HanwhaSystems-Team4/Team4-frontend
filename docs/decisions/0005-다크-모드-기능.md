# 0005. 다크 모드를 후보가 아닌 기능으로 둔다

- 상태: 결정됨
- 날짜: 2026-10-23
- 작성: 문선웅
- 관련: [0004](0004-AB-테스트용-디자인-후보-3개.md), `packages/ui/src/theme-mode.tsx`, `packages/ui/src/styles/dark.css`

## 배경

A/B 후보로 만든 "D 야간 관제형"을 보고, 어두운 화면은 디자인 후보로 고를 것이 아니라 **사용자가 설정에서 다크 모드를 고르면 어두워지는 기능**이면 된다는 의견이 나왔다.
야간 교대(22:00 ~ 06:00) 현장에서는 밝은 화면이 눈부실 수 있어, 어떤 디자인을 고르든 어둡게 볼 수 있어야 한다.

## 후보

| | A. 디자인 후보 하나(D)로 둠 | B. 운영체제 설정(prefers-color-scheme)만 따름 | C. 화면 안 버튼 + 기기에 기억 |
| --- | --- | --- | --- |
| 하는 일 | D를 고를 때만 어두움 | 기기가 다크면 자동으로 어두움 | 상단 '다크' 버튼으로 켜고 끔, 이 기기에 기억 |
| 장점 | 만들 것 적음 | 손댈 것 없음 | 누구나 바로 바꿈, 디자인 후보와 따로 |
| 단점 | 다른 후보는 어둡게 못 봄 | 공용 태블릿에서 사용자가 못 바꿈 | 버튼 하나가 화면에 늘어남 |

## 결정

**C.** 정비자 앱은 상단 바(시계 왼쪽), 파트장 앱은 본문 머리(제목 줄 오른쪽)에 '다크' 버튼을 둔다. 누르면 `<html data-theme="dark">`가 붙고 `styles/dark.css`가 색만 바꾼다. 고른 값은 이 기기(localStorage `team4.theme`)에 남는다. 주소에 `?theme=dark`를 붙이면 발표 · 캡처용으로 바로 어둡게 연다.

## 이유

- 디자인 후보(A ~ C) 어느 것을 골라도(산업 관제형 C도 [0009](0009-C-홈-알람-통합-표와-라이트-다크.md)부터 라이트 · 다크를 모두 가진다) 어둡게 볼 수 있어야 한다 → `html[data-theme]` 선택자로 후보 CSS 위에 덧씌운다.
- 공용 태블릿을 교대로 쓰므로 운영체제 설정보다 화면 안 버튼이 맞다.
- 화면 구성 · 순서 · 클래스는 바뀌지 않는다(버튼 하나 추가). 화면 테스트 85개가 그대로 통과한다.

## 영향

- 추가: `packages/ui/src/theme-mode.tsx`(`initThemeMode`, `ThemeToggle`), `packages/ui/src/styles/dark.css`, 아이콘 `moon` · `sun`
- 변경: `TopBar`(정비자 상단 바)와 파트장 앱 `Frame` 본문 머리에 다크 모드 버튼, 두 앱 `main.tsx`에서 `initThemeMode()`와 `dark.css`
- 어두운 색: 바탕 #0d1217, 카드 #161d24, 글자 #e6edf3. 상태 색은 어두운 바탕에서 읽히는 밝은 톤(빨강 #ff5d63, 노랑 #f5b13d, 초록 #3fd27f). 등급 배지 색의 의미는 그대로.

## 다시 검토할 조건

- 사용자 설정 화면이 생기면 버튼을 그 화면으로 옮긴다.
- 계정별로 기억해야 하면(여러 기기에서 같은 설정) 백엔드에 설정 저장 API가 필요하다.
