# 0010. D "페이지 수정": C를 이어받아 진단 3열 · 점검과 조치 통합 · 알람 단계 이름 바꾸기

## 배경

C 산업 관제형을 보다가 나온 의견이다.

- 점검할 때 **왼쪽에 센서 데이터가 있으면 LLM의 판단(원인 순위 · 다음 점검)이 맞는지 확인하기 쉽다.** 시안(03 Industrial Operations)의 진단 화면도 센서 | 원인 순위와 유사 기록 | 다음 점검 3열이다.
- 점검과 조치를 한 단계로 합치고 싶다.
- 알람 화면의 이름이 실제 화면과 맞지 않는다. 이 화면에는 센서 값이 있고 무엇이 정상 범위를 벗어났는지 확인할 수 있다.

화면 순서와 구성이 바뀌는 의견이라 C를 고치지 않고 **분기로 새 후보 D "페이지 수정"** 을 만든다. 비교 발표를 하므로 A · B · C · E는 바꾸지 않는다.

## 결정

D = C 전체(색 · 라이트/다크 · 홈 표 · 문구 · 1280 × 800)를 그대로 이어받고, 아래 세 가지만 D에서 다르다.

1. **진단 화면 3열.** 왼쪽에 "센서 값 · 알람 시점" 패널(센서 이름 · 값 · 평소 범위 · 상태, 범위 밖은 빨강)을 더한다. 값과 상태는 세션 응답의 알람 블록(`alarm.sensors`)이 준 것 그대로다. 그 센서 패널은 D 외 화면에서는 숨긴다.
2. **점검과 조치를 한 단계로.** 진행 레일이 알람 · 진단 · 점검 · 조치 · 보고서 5칸에서 **센서 확인 · 진단 · 점검·조치 · 보고서의 4칸**(점검과 조치를 "점검·조치" 한 칸으로)으로 보인다. 점검 중이든 조치 중이든 같은 칸이 현재 단계이고, 지난 화면에서 그 칸을 누르면 점검과 조치 기록을 이어서(이전 · 다음) 본다. 서버의 단계 구분은 그대로이고 화면의 칸만 합친다.
3. **알람 단계 이름 → "센서 확인".** 알람 화면은 센서 값을 보고 어느 센서가 정상 범위를 벗어났는지 확인하는 화면이라 이름을 맞춘다(진행 레일과 지난 화면 띠). 상단 빨간 `ALARM` 띠와 홈의 알람 상태는 알람 자체를 가리키므로 그대로다.

## 후보: 단계를 합치는 방법

| | 가. 서버 · 화면 모두 4단계로 | 나. 화면 칸만 합침 |
| --- | --- | --- |
| API · 서버 | 단계 번호 · 지난 화면 응답을 바꿔야 함(백엔드 수정) | 그대로 |
| 다른 후보 | 영향 | 영향 없음(CSS와 D에서만 쓰는 값) |

**나.** 진행 레일의 칸을 CSS로 합치고(조치 칸 숨김, 점검 칸을 "점검 · 조치"로, 조치 중에는 점검 칸이 현재 단계), 지난 화면은 D일 때 점검과 조치 기록을 한 목록으로 이어 붙인다.

## 바뀌는 것 / 바뀌지 않는 것

- 추가: `variants/d-page-edit.css`, 후보 목록의 D, 진단 화면의 센서 패널(D만 보임), 지난 화면 띠의 단계 번호 값
- 변경: C의 CSS 선택자가 D에도 걸린다(`:is([data-variant="c"], [data-variant="d"])`)
- 안 바뀜: A · B · C · E 화면, API, 서버의 단계 구분, 화면 이동 순서

## 다시 검토할 조건

- D가 선택되면 점검과 조치를 합친 4단계를 평소 디자인과 서버에도 옮길지 새 결정 기록으로 정한다.
- 센서 패널에 막대(평소 범위 안 위치)를 더하려면 서버가 범위를 숫자로 줘야 한다(지금은 "1,305 ~ 1,979" 같은 글이다).
