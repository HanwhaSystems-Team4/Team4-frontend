# 0001. 프론트엔드를 npm workspaces 모노레포로 구성

- 상태: 결정됨
- 날짜: 2026-10-16
- 작성: 문선웅

## 배경

프론트엔드에 화면 묶음이 셋 생겼다. 정비자 앱, 파트장 앱, 설비 이상 대시보드다. 백엔드는 요청의 `X-App` 헤더(`tech` / `lead`)와 앱별 세션 쿠키(`tech_session` / `lead_session`)로 정비자 앱과 파트장 앱을 구분하고, 계정 역할이 앱과 맞지 않으면 로그인을 거절한다. 세 화면 묶음을 한 레포에서 어떻게 나눌지 정해야 한다.

## 후보

| | A. 한 앱 안에 라우트로 합치기 | B. npm workspaces 모노레포 | C. 앱마다 레포 분리 |
| --- | --- | --- | --- |
| 하는 일 | `/tech/*`, `/lead/*`, `/dashboard`를 react-router 한 앱에 | `apps/tech`, `apps/lead`, `apps/dashboard` + 공통 `packages/ui` | 레포 3개 |
| 백엔드 앱 구분(`X-App`) | 요청마다 헤더를 바꿔야 하고 두 쿠키가 한 화면에 섞임 | 앱별 개발 서버 프록시가 헤더를 붙임. 배포 시 nginx 포트별 설정과 같은 모양 | B와 같음 |
| 공통 코드 | 같은 앱이라 바로 씀 | `packages/ui`로 공유 | 복사하거나 패키지 배포 필요 |
| 설치·테스트 | 한 번 | 루트에서 `npm install` 한 번, `npm test` 한 번 | 레포마다 |
| 앱끼리 영향 | 한 번들이라 서로 영향 | 앱끼리 import하지 않음 | 완전히 분리 |

## 결정

**B. npm workspaces 모노레포.**

## 이유

- 백엔드가 앱을 `X-App` 헤더와 쿠키 이름으로 구분하므로, 앱마다 개발 서버를 따로 두는 쪽이 백엔드 구조와 그대로 맞는다. A는 이 구분을 프론트에서 흉내 내야 한다.
- 설치·타입 검사·테스트·빌드를 루트 명령 하나로 돌릴 수 있어 테스트가 쉽다. C는 레포마다 반복해야 한다.
- 상단 바, 진행 표시, 등급 배지, API 클라이언트, 디자인 테마를 `packages/ui` 하나로 공유한다.

## 영향

- 기존 로그인·대시보드 코드는 `apps/dashboard`로 옮겼다(내용 변경 없음).
- TypeScript는 7로 통일했다. 대시보드도 그대로 타입 검사를 통과한다.
- 명령은 루트 `package.json`의 `dev:tech` · `dev:lead` · `dev:dashboard` · `test` · `typecheck` · `build` · `lint` · `api:types`.

## 다시 검토할 조건

- 대시보드가 실제 백엔드 API에 붙으면서 정비자·파트장 앱과 로그인을 공유해야 할 때
- 배포 방식이 nginx 포트별 구성에서 바뀔 때
