# 0009. 산업 관제형(C): 홈과 알람 화면을 합친 보고서 목록 표, 라이트(흰색) · 다크

- 상태: 제안
- 날짜: 2026-10-29
- 작성: 문선웅
- 관련: [0007](0007-AB-테스트-후보-재구성과-산업-관제형.md), [0008](0008-홈-설비-표와-정렬.md), [0005](0005-다크-모드-기능.md)

## 배경

산업 관제형(C)의 홈을 더 다듬는다는 의견이 나왔다.

- 홈과 알람 화면을 합쳐 본다. 홈은 "내 알람"이 아니라 **보고서 목록을 채운 표**로 보이고, 표에 설비 · 이상 상태 · 알람 화면에 있던 센서 값 · 현재 진행 상태를 열로 둔다.
- 마지막 열은 상태다. 원래 알람으로 뜨던 것은 **작성 바람**, 알람을 끝낸(보고서를 확정한) 것은 **승인 대기**로 보인다.
- 위에는 처리 완료 · 진행 중 · 파트장 호출 숫자만 간략히 둔다. 안전 수칙은 점검(잠금) 화면에 있으므로 홈에서 뺀다. 오늘 교대 시간은 현재 시각과 겹쳐서 슬라이더로 보인다.
- 알람 화면은 추이 그래프와 AI 해석을 더 강조한다.
- 진행 단계는 알람 · 진단 · 점검 · 조치 · 보고서를 그대로 둔다.
- C에도 다크 모드를 넣고, 라이트 모드는 흰색으로 한다.

## 가능한 범위

홈 API의 알람 행에는 설비 번호, 증상군 이름, 알람 값 · 경계 · 방향, 발생 시각, 상태, 진행(점검 n / 최대 m), 보고서 상태, **센서 스냅샷(회전수 · 토크 · 공구 마모 · 공정 온도 · 전력 등)** 이 들어 있다. 표의 열은 이 값만으로 채운다.
교대 시각은 `shift.start_text` / `end_text`(예: 22:00 ~ 06:00)이고 슬라이더 위치는 지금 시각으로 계산한다(표시용 계산이고 판정 값이 아니다).
알람이 없는 설비 목록은 여전히 API에 없다([0008](0008-홈-설비-표와-정렬.md)).

## 후보

| | 가. 홈 화면 코드를 C용으로 따로 만든다 | 나. 같은 화면 코드에 열을 더하고 C에서만 보인다 |
| --- | --- | --- |
| A · B · E 홈 | 영향 없음 | 숨겨져 지금과 같음 |
| 화면 코드 | 홈이 둘 | 하나(열 · 슬라이더 칸만 추가) |
| 기존 시험 | 새로 | 그대로 통과 |

## 결정

**나.** `HomeScreen`에 센서 칸(`.al-s`) · 보고서 상태 칸(`.al-r`) · 교대 슬라이더(`.shift-bar`)를 더하고, C 외에는 CSS로 숨긴다. 상태 이름은 새 알람 · 점검 중 = 작성 바람, 보고서 확정 = 보고서 상태 이름(승인 대기 · 승인 완료 · 반려).

C의 색은 두 벌로 나눈다.

- 라이트(기본): 흰 바탕, 회색 테두리, 정상 회색 · 경계 이탈 빨강 · 승인 필요 주황 · 선택 · AI 하늘색(글자로 쓸 때는 어두운 하늘색).
- 다크: 지금의 어두운 관제 색.

C에서 '다크' 버튼을 다시 보이고, `dark.css`의 공통 규칙은 C에 걸리지 않게 한다(C는 자기 다크 색을 가진다).

표의 반투명은 승인까지 끝난 설비(승인 완료)에만 쓴다([0008](0008-홈-설비-표와-정렬.md)의 "완료 = 반투명"을 이 기준으로 바꾼다). 승인 대기 설비는 상태를 읽어야 하므로 또렷하게 둔다.

## 보강(2026-10-29)

- **화면 틀:** 웹 데모이고 갤럭시 탭도 가로가 길어서, C의 화면 틀을 1080 × 740에서 **1280 × 800**(16:10)으로 넓힌다. 다른 후보는 그대로다.
- **센서 열:** 알람 화면의 센서 표와 같은 5개(온도 차 · 회전 속도 · 회전력 · 공구 마모 · 공기 온도)를 열로 나눈다. 이름은 알람 화면과 같고, 알람을 낸 센서는 빨강이다. 그 센서의 값은 센서 칸에 있으므로 "경계" 열에는 경계(예: 경계 아래 · 8.3)만 보인다(알람을 낸 센서가 5개 안에 없으면 이상 값도 함께 보인다). 대신 진행 열에서 시각을 빼서 자리를 맞춘다(예: "점검 1 / 최대 3 진행 중").
- **보고서 행:** "최근 내 보고서"(승인 대기 · 승인 완료 · 반려)도 표에 행으로 나온다. 행의 색이 알람 행과 다르다(승인 대기 = 주황 띠, 승인 완료 = 초록 띠 · 반투명, 반려 = 빨강 띠). 같은 보고서가 알람 행(이 교대에 확정한 것)으로 이미 보이면 한 번만 보인다(보고서 세션 번호로 구분). 보고서 행의 "보기"는 그 세션 화면을 연다.
- 알람이 없는 설비 목록이 API에 없는 점은 그대로다.

## 보강 2(2026-10-29): 문구와 유사 기록 표시 — C만

비교 발표를 하므로 **C 산업 관제형만 바꾸고 A · B · E는 바꾸지 않는다.** 공통 화면 코드에는 C에서만 쓰는 값(`data-n` · `data-k` · `data-rest`)을 더하고, 문구 바꿈은 C의 CSS(`attr()` + `::after`)로만 한다. A · B에서는 지금 화면과 똑같다.

- **"센서 n개 이탈" → "안정 범위 밖 n개".** "센서 이탈"은 센서 장치가 고장난 것처럼 읽힌다. 실제 뜻은 센서 값이 안정 범위 밖이라는 것이다.
- **"안정 범위 밖 n개"의 n은 서버가 센다.** 서버(`out_of_range_count`)는 알람 경계가 있는 센서 4개(기계 출력 · 온도 차 · 토크 · 공구 마모)를 모두 비교해 센다. 그런데 알람 화면 표는 5행만 보여서(알람 센서 + 4개) 표에 없는 센서가 안정 범위 밖이면 표에는 1개인데 숫자는 2개가 된다(예: 기계 출력 알람인 M-12는 온도 차 8.0 K가 경계 8.3 K 아래인데 표에 온도 차 행이 없다). C에서는 숫자 뒤에 "표에 없는 n개 포함"을 붙여 표와 숫자가 맞도록 한다. 서버 규칙(표에 없는 센서도 센다)은 바꾸지 않는다.
- **n건 중 상위 k건의 n:** 알람 블록의 `similar_count`(서버가 세션에 저장한 유사 기록 수, 지금은 10)다. 지난 화면(T15)의 진단 기록에는 알람 블록이 없어서 알람 단계 기록의 알람 블록을 가져다 쓴다. 그것도 없으면 근거 합계(상위 10건 기준)로 센다.
- **"비슷한 과거 기록 k건 · 상위 10건 중" → "비슷한 과거 기록 n건 중 상위 k건".** 원래 화면은 n과 k가 거꾸로다. n은 찾은 전체(알람 화면의 "비슷한 과거 기록 n건을 찾았습니다"와 같은 값), k는 지금 보이는 카드 수다.
- **상위 k건 강조:** 카드에 순위(1 · 2 · 3)와 하늘색 강조 테두리를 주고, 아래에 그 밖의 건수("그 밖의 비슷한 기록 n − k건")를 보인다.
- **한계:** 세션 API는 상위 3건 카드(`similar_cards`)와 찾은 건수(`similar_count`)만 준다. 나머지 기록의 목록은 없어서 "모든 비슷한 과거 기록을 나열"하려면 API에 유사 기록 목록이 더해져야 한다(백엔드는 수정하지 않는다).
